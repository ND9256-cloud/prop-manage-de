## What changed direction

Phase 1 (deploy + test on 8 grundbuchauszug docs) is paused, not cancelled. Reason: extraction quality is the moat, and the current `extraction_schemas.ts` design lacks foundational primitives (provenance/evidence, claim layer, lifecycle support, severity classes, multi-provider routing, deterministic verifiers). Shipping Phase 1 as-built would lock in an architecture that needs to be rewritten in 3-6 months.

A v2 architecture redesign is in progress, sequenced as 4 research passes before any production work resumes.

## Architectural primitives to be locked in v2

These are decided and will appear in the Pass 1 architecture document. Implementation tasks will follow once the document is approved.

1. **Common extraction envelope.** Every extracted field carries: `raw_value`, `normalized_value`, `evidence` (quote, page, optional bbox), `confidence` (high/med/low), `absence_state` (one of 8: present/absent/illegible/ambiguous/contradicted/not_applicable/inferred/requires_human_review), `validation_status`. Document level adds: `schema_version`, `prompt_version`, `model`, `extraction_run_id`, `source_document_id`, document lifecycle (`issue_date`, `effective_date`, `expiry_date`, `signed_date`, `document_status`, `supersedes_document_id`, `amended_by_document_id`), `human_review_status`.

2. **Claim layer.** New persistence layer between extractions and the property brain. Claims are temporal assertions: `{subject, predicate, value, valid_from, valid_to, source_document_id, source_field, confidence, evidence_id}`. Append-only. Each extracted field can emit zero, one, or many claims.

3. **Resolution layer.** Resolvers convert claims to current property facts. First resolver to be fully designed: `rent_for_unit(property_id, unit_ref, as_of_date)`. Other resolvers follow the same pattern.

4. **Domain knowledge layer.** Markdown files in `domain_knowledge/<doc_type>.md` with structured front-matter. Single source of truth for legal grounding, normalization rules, German abbreviations, gotchas. Consumed by prompts, schemas, brain, and resolvers — not duplicated across them.

5. **Authoring primitive.** Domain YAML as source of truth for schemas. Generator (TypeScript, ~200-300 lines) produces JSON Schema, Zod, TypeScript types, prompt fragments, FIELD_LABELS, eval rubric. Generator to be built after Pass 1 approval, before Pass 2 schemas are written.

6. **Multi-provider extraction routing.** Architecture supports Sonnet, Opus, and GPT-5 (via OpenAI API) as routing targets. Eval harness tests all three on every doc type. Production routes per-doc-type to the eval winner. Ship Anthropic-only at launch, add GPT-5 routing when eval shows it winning on a specific doc type.

7. **Deterministic verifiers.** Per-field rules that catch domain-blind LLM errors on critical-severity fields. Examples: monetary values must appear verbatim in OCR text; dates must parse; enum values must match dictionary; boolean derivations must be checkable against keyword presence/absence.

8. **Three-role labeling.** Extractor (Sonnet) / Critic (Opus or GPT-5, model-diverse) / Human adjudicator (Nils).

9. **Eval and adjudication design.** Field-level metrics, severity-weighted, abstention-aware, evidence-correctness-aware. Frozen test set, dev set for iteration, adversarial set for stress. Nightly CI run.

10. **Active learning loop.** Triage UI corrections automatically become gold-set candidates.

11. **Adversarial fixtures.** Synthetic documents generated by Claude covering edge cases real corpus doesn't hit at frequency.
